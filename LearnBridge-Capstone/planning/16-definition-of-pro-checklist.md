# Definition of Pro, a Closing Checklist

This is the test this whole plan was built to prepare you for. Go through it once when LearnBridge is finished, honestly, without opening the code to check yourself first. Every item traces back to a specific concept from the eight source folders, listed so you can go back and reread the exact note if an item does not come easily.

1. Explain, in one breath, what a NestJS module, controller, service, and provider each are, and how dependency injection connects them, without the word "decorator" doing all the work in your explanation. Traces to `01-introduction-to-nestjs.md` through `07-dependency-injection.md`.
2. Explain why Enrollment needed to be its own database entity instead of a plain array of ids on either side of the relationship, and give one other real world example of a many to many relationship that would need the same treatment. Traces to `04-data-model-and-relationships.md` and the many to many notes in the MongoDB reference project.
3. Explain why the order and enrollment creation had to happen inside one transaction, and describe, concretely, what could go wrong in production if they did not. Traces to phase 5's PRD.
4. Explain why notifications live in MongoDB while everything else lives in Postgres, using the actual tradeoff, not just "because MongoDB is more flexible" as a memorized line. Traces to `10-relationship-concepts-from-lecture.md` in the MongoDB reference project and `02-tech-stack-and-architecture.md` here.
5. Explain the exact difference between what a guard checks and what a service level ownership check catches, and give the concrete example of an instructor editing another instructor's course to show why one alone is not enough. Traces to phase 2 and phase 3's PRDs.
6. Explain why a global `ValidationPipe` is necessary even when every DTO already has `class-validator` decorators on it, using the specific inert validation gap found in the GraphQL reference project as the cautionary example. Traces to `04-input-types-and-validation.md` in the GraphQL reference project.
7. Explain the actual difference between a REST controller method and a GraphQL resolver method that call the exact same service, and why LearnBridge deliberately never wrote two separate implementations of the same lookup logic. Traces to phase 7's PRD.
8. Explain why nearly every spec file across all eight reference projects failed the moment it was actually run, in your own words, and show one real example from your own LearnBridge test suite where you deliberately avoided that mistake. Traces to `09-testing-gaps.md` in the MongoDB reference project and phase 9's PRD here.
9. Explain what would have happened to this project's login endpoint under brute force attempts if rate limiting were never added, and why the per route override on login needed to be stricter than the global default rather than equal to it. Traces to phase 8's PRD and the identical override bug found in the Throttler reference project.
10. Sit down in front of a blank editor, pick any one feature not yet built anywhere in LearnBridge, something small, and build it end to end, DTO, service, controller, guard, and a test, in one sitting, without opening any of these planning files or the eight reference notes folders even once. This last item is the real test. Everything above it is preparation for being able to do this on your own, on a feature you have never seen a reference implementation for, which is the actual definition of being proficient rather than having followed instructions well.
